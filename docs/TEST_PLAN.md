## Release gate

Never mark as stable or publish a "100% no disconnect" guarantee. Require successful CI, user-permission checks, device tests, and repeated real match observations. A debug APK generated by CI is not proof of these conditions.

## New v0.2 acceptance checks

| Test | Expectation |
|---|---|
| Rotate screen after profile import | Profile remains in app process memory; private keys never persisted |
| Match protection toggled ON | Two HTTPS watchdog failures WARN only, do not deliberately switch routes |
| Match protection OFF | Repeated health-check failures request a best-effort VPN stop |
| Direct vs VPN comparison | Both measurements use same HTTPS target, do not change VPN configuration |
| Primary test endpoint unreachable | Comparison uses the SECOND HTTPS endpoint for BOTH routes |
| VPN disconnect failure | App displays warning instead of falsely claiming a safe fallback |
| Process killed and restarted | Profile needs manual re-import; no embedded credentials or silent reconnect |

These scenarios require real device validation. WireGuard configured VPN and server availability are prerequisites.

## New v0.3 critical fault tests

- [x] `TunnelHandshake`: accept fresh peer handshake; reject zero, too old or implausibly far-future timestamps.
- [x] `ProbeSummary`: never compute jitter across missing HTTP measurements.
- [x] `HealthDecision`: two failures are not enough to request automatic shutdown; at least three are needed outside match protection.
- [ ] Full Gradle/Android compilation + Android lint with an accessible SDK.
- [ ] Verify VpnService behavior on Android 14/15/16 and OEM background restrictions.
- [ ] On-device test: reboot/restart, rotated Activity while VPN permission dialog is open, coexistence with an existing VPN.
- [ ] Capture three comparable sessions on Wi-Fi and cellular with a legally operated WireGuard relay.

## v0.4 benchmark and safety regression tests

- [x] ABBA / BAAB covers an equal number of direct and VPN transactions.
- [x] A changing network cancels the entire trial instead of comparing partial samples.
- [x] Failed transactions retain failure counts (no fabricated latency values).
- [x] Insufficient trial count is explicitly rejected.
- [x] A relay with a single extreme P95 outlier is not recommended.
- [x] Too many HTTP request failures yields INSUFFICIENT_DATA.
- [x] Tiny absolute gains are not advertised as meaningful.
- [ ] Real Android instrumented tests: swap Wi-Fi → mobile in the middle of the ABBA pass.
- [ ] Confirm pending VPN state resets correctly after revoked Android VPN consent.
- [ ] Build an APK with Android SDK and use a real authorized WireGuard relay.

Note: v0.4's 25 test methods were executed through a minimal local Java JUnit
compatibility stub with Kotlin/JVM compiler 1.9.0. They do **not** substitute
for a real Android Gradle build or test runner.
